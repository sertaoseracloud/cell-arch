<objective>
Build the reusable `aws-vpc` Terraform module that provisions a Hub-Spoke VPC topology for the EKS workload environment. The Hub VPC centralises NAT Gateway traffic; the Spoke VPC hosts EKS nodes in private subnets only. DynamoDB traffic is routed through a VPC Gateway Endpoint — never over the public internet.

Purpose: TERR-01 requires private-only VPC; SECR-03 requires all compute resources in private subnets. The Gateway Endpoint (Pattern 6 from RESEARCH.md) eliminates any public-internet path to DynamoDB.

Output: infra/modules/aws-vpc/ with main.tf, variables.tf, outputs.tf — ready to be called by infra/live/aws/{dev,hom,prod}/.
</objective>

Hub VPC — CIDR 10.0.0.0/16, two private AZ subnets (/22 each for EKS IP space), NAT Gateway, IGW (Hub only — for NAT egress), private route table routing 0.0.0.0/0 → NAT:
- `aws_vpc.hub` — cidr_block = "10.0.0.0/16", enable_dns_hostnames = true, enable_dns_support = true
- `aws_internet_gateway.hub` — attached to aws_vpc.hub (Hub VPC needs IGW for NAT Gateway outbound)
- `aws_subnet.hub_private_a` — cidr_block = "10.0.0.0/22", availability_zone = "${var.aws_region}a", map_public_ip_on_launch = false
- `aws_subnet.hub_private_b` — cidr_block = "10.0.4.0/22", availability_zone = "${var.aws_region}b", map_public_ip_on_launch = false
- `aws_eip.nat` — domain = "vpc"
- `aws_subnet.hub_nat` — cidr_block = "10.0.8.0/28", availability_zone = "${var.aws_region}a", map_public_ip_on_launch = false (NAT GW subnet — no public IP on instances, but NAT GW itself needs an EIP and a path to IGW)
- `aws_nat_gateway.hub` — allocation_id = aws_eip.nat.id, subnet_id = aws_subnet.hub_nat.id
- `aws_route_table.hub_nat_subnet` — vpc_id = aws_vpc.hub.id with route 0.0.0.0/0 → aws_internet_gateway.hub (only for the NAT GW subnet)
- `aws_route_table_association.hub_nat_subnet` — associates hub_nat subnet with hub_nat_subnet route table
- `aws_route_table.hub_private` — vpc_id = aws_vpc.hub.id with route 0.0.0.0/0 → aws_nat_gateway.hub
- `aws_route_table_association.hub_private_a` and `hub_private_b`

Spoke VPC — CIDR 10.1.0.0/16, two private AZ subnets (/22), no IGW, traffic egresses via peering → Hub NAT:
- `aws_vpc.spoke` — cidr_block = "10.1.0.0/16", enable_dns_hostnames = true, enable_dns_support = true
- `aws_subnet.spoke_private_a` — cidr_block = "10.1.0.0/22", availability_zone = "${var.aws_region}a", map_public_ip_on_launch = false
- `aws_subnet.spoke_private_b` — cidr_block = "10.1.4.0/22", availability_zone = "${var.aws_region}b", map_public_ip_on_launch = false
- `aws_route_table.spoke_private` — count = 2, vpc_id = aws_vpc.spoke.id; route 0.0.0.0/0 → aws_vpc_peering_connection.hub_spoke (so egress goes through Hub's NAT)
- `aws_route_table_association.spoke_private_a` and `spoke_private_b`

VPC Peering:
- `aws_vpc_peering_connection.hub_spoke` — vpc_id = aws_vpc.hub.id, peer_vpc_id = aws_vpc.spoke.id, auto_accept = true
- `aws_route.hub_to_spoke` — route_table_id = aws_route_table.hub_private.id, destination_cidr_block = "10.1.0.0/16", vpc_peering_connection_id = aws_vpc_peering_connection.hub_spoke.id
- `aws_route.spoke_to_hub` (per count = 2 route tables) — destination_cidr_block = "10.0.0.0/16", vpc_peering_connection_id = aws_vpc_peering_connection.hub_spoke.id

DynamoDB Gateway Endpoint (per RESEARCH.md Pattern 6):
```hcl
resource "aws_vpc_endpoint" "dynamodb" {
  vpc_id            = aws_vpc.spoke.id
  service_name      = "com.amazonaws.${var.aws_region}.dynamodb"
  vpc_endpoint_type = "Gateway"
  route_table_ids   = aws_route_table.spoke_private[*].id

  tags = merge(var.tags, {
    Name = "${var.project_name}-dynamodb-ep-${var.environment}"
  })
}
```

All resources must include a `tags` argument: `merge(var.tags, { Name = "..." })`.
