<objective>
Create a dedicated **Observability Sidecar** that runs the OpenTelemetry Collector as a DaemonSet, configured to export traces to Jaeger and metrics to Prometheus.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Scaffold Observability Sidecar binary</name>
  <files>cmd/obs-sidecar/main.go</files>
  <action>
    • Create `cmd/obs-sidecar/main.go` with a minimal `main()` that:
      - Loads `internal/observability/collector_config.yaml`.
      - Starts the OpenTelemetry Collector binary (`otelcol-contrib`) as a child process.
      - Exposes a health-check HTTP endpoint (`/healthz`) returning 200 when the collector is running.
    • Add Go module imports for `os/exec` and `net/http`.
  </action>
  <verify>
    <automated>go test ./cmd/obs-sidecar -run TestSidecarStartup -count=1</automated>
  </verify>
  <done>Binary builds successfully and `./obs-sidecar` launches the collector process; health endpoint returns 200.</done>
</task>

<task type="auto">
  <name>Task 2: Add Collector configuration file</name>
  <files>internal/observability/collector_config.yaml</files>
  <action>
    • Create a YAML config containing:
      - Receivers: `otlp` (grpc & http), `prometheus`.
      - Processors: `batch`, `memory_limiter`.
      - Exporters: `jaeger` (endpoint `http://jaeger-collector:14268/api/traces`) and `prometheus` (endpoint `0.0.0.0:9464`).
      - Service pipelines for `traces` → `[batch]` → `jaeger` and `metrics` → `[batch]` → `prometheus`.
    • Include a `sampler` with `traceIDRatioBased: 0.10` and a `tail_sampling` rule for error spans (status ≥ 5xx).
  </action>
  <verify>
    <automated>otelcol-contrib --config internal/observability/collector_config.yaml --dry-run</automated>
  </verify>
  <done>Collector validates the config without runtime errors.</done>
</task>

<task type="auto">
  <name>Task 3: Deploy Collector DaemonSet</name>
  <files>deploy/observability/collector-daemonset.yaml</files>
  <action>
    • Write a Kubernetes DaemonSet manifest that:
      - Mounts `collector_config.yaml` via a ConfigMap.
      - Runs `otelcol-contrib --config /conf/collector_config.yaml`.
      - Exposes port 9464 for Prometheus scraping.
      - Sets resource limits (cpu: 200m, memory: 256Mi) and requests.
      - Adds pod anti-affinity to spread across nodes.
    • Add a corresponding ConfigMap resource for the YAML config.
  </action>
  <verify>
    <automated>kubectl apply -f deploy/observability/collector-daemonset.yaml --dry-run=client</automated>
  </verify>
  <done>DaemonSet YAML passes `kubectl apply --dry-run` and creates expected resources.</done>
</task>

</tasks>
