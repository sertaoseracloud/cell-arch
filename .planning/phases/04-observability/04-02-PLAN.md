<objective>
Initialize the OpenTelemetry SDK in **both** the main application and the existing sidecar, wiring the singleton tracer provider to the collector endpoint.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Add tracer initializer helper</name>
  <files>internal/observability/tracer.go</files>
  <action>
    • Implement `func InitTracer(serviceName string) (*sdktrace.TracerProvider, error)` that:
      - Creates Jaeger exporter (`jaeger.NewExporter` with collector endpoint `http://jaeger-collector:14268/api/traces`).
      - Configures sampler `TraceIDRatioBased(0.10)` and tail-sampling for error spans.
      - Registers `otel.SetTracerProvider(tp)` and `otel.SetTextMapPropagator(propagation.TraceContext{})`.
      - Returns the `TracerProvider` so callers can defer `tp.Shutdown(context.Background())`.
    • Use `go.opentelemetry.io/otel/sdk/trace` and `go.opentelemetry.io/otel/exporters/jaeger`.
  </action>
  <verify>
    <automated>go test ./internal/observability -run TestInitTracer -count=1</automated>
  </verify>
  <done>Tracer provider builds, returns without error, and `Shutdown` completes cleanly.</done>
</task>

<task type="auto">
  <name>Task 2: Wire tracer into cmd/app</name>
  <files>cmd/app/main.go</files>
  <action>
    • Import `internal/observability`.
    • At program start, call `tp, err := observability.InitTracer("cell-arch-app")`.
    • Defer `tp.Shutdown(context.Background())`.
    • Ensure any existing logger is created **after** tracer init so `slog` can attach `trace_id`.
  </action>
  <verify>
    <automated>go run ./cmd/app & sleep 2; curl -s http://localhost:8080/healthz | grep OK</automated>
  </verify>
  <done>App starts, health endpoint returns 200, and a trace is visible in Jaeger when a request is made.</done>
</task>
