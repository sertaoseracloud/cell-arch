<objective>
Expose Prometheus metrics from both binaries, register custom observation metrics, and provide Grafana dashboards aligned with Well-Architected, FinOps, and GreenOps concepts.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Register OpenTelemetry Prometheus exporter</name>
  <files>internal/observability/metrics.go</files>
  <action>
    • Create a function `InitMetrics()` that:
      - Registers the `prometheus.NewExportPipeline` with the global MeterProvider.
      - Creates custom instruments:
        * `request_latency_seconds` (Histogram) with `cloud_provider`, `service`, `status_code` labels.
        * `sidecar_read_rps` (Counter) for per-second read throughput.
      - Starts a background goroutine that calls `otelcol`'s Prometheus receiver (already in collector config).
    • Call `InitMetrics()` from both `cmd/app/main.go` and `cmd/sidecar/main.go` after tracer init.
  </action>
  <verify>
    <automated>curl -s http://localhost:9464/metrics | grep request_latency_seconds</automated>
  </verify>
  <done>Metrics endpoint returns the custom metric families.</done>
</task>

<task type="auto">
  <name>Task 2: Structure logs with trace context</name>
  <files>internal/logging/logger.go</files>
  <action>
    • Ensure the logger is built with `log/slog.New(slog.JSONHandler(os.Stdout, nil))`.
    • Add a helper `func WithTrace(ctx context.Context) []slog.Attr` that extracts `trace.SpanContext` and returns `trace_id` and `span_id` attributes.
    • Wherever the logger is used (e.g., in middleware, usecases), include `slog.With(WithTrace(ctx)...)`.
  </action>
  <verify>
    <automated>go test ./internal/logging -run TestWithTrace -count=1</automated>
  </verify>
  <done>Log lines emitted are valid JSON and contain `trace_id` and `span_id` fields.</done>
</task>

<task type="auto">
  <name>Task 3: Add Grafana dashboard JSON files</name>
  <files>deploy/observability/grafana-dashboards/</files>
  <action>
    • Create three dashboard JSON files:
      - `well-architected.json` (latency, error rate, request volume).
      - `finops.json` (cost per request, per-cloud request counts, request-size bytes).
      - `greenops.json` (CPU/memory utilisation, estimated CO₂e per request using Cloud Carbon Footprint labels).
    • Each dashboard references the Prometheus data source `Prometheus` (assume it exists in the Grafana instance).
    • Add a brief README describing how to import them via Grafana UI.
  </action>
  <verify>
    <automated>test -f deploy/observability/grafana-dashboards/well-architected.json && echo ok</automated>
  </verify>
  <done>All three JSON files are present and syntactically valid (checked with `jq .`).</done>
</task>

</tasks>
